# AGENTS.md — Fast Math

Fast Math is a mental arithmetic game for GNOME. The player picks a mode,
arithmetic (addition, subtraction, multiplication, division, in any mix) or
comparison (less than, equal to or greater than), a level and a time limit,
then answers up to 60 questions. The app ID is `io.github.nacho.fastmath`.

It is written in Rust (edition 2024) with GTK 4.20 and libadwaita 1.8 (the
`v4_20` and `v1_8` features). Meson builds it for production and Cargo for
development. Types use the `Fastmath` prefix.

## Directory Map

```
src/
  main.rs               # i18n, resources, logger, G_LOG_DOMAIN
  config.rs.in          # Template for config.rs, generated by build.rs
  application.rs        # FastmathApplication: actions (the sound effects toggle is the
                        # `app.sound-effects` GSettings action), CSS, About, shortcuts dialog
  window.rs             # FastmathWindow: AdwNavigationView flow, window state
  start_view.rs         # Mode, operation or comparison switches, level, time limit, Start
  game_view.rs          # The round: question, entry or < = > buttons, clock, sounds,
                        # abandon dialog
  results_view.rs       # Score, leaderboard, name entry, Play Again / Back
  sound_player.rs       # gtk::MediaFile wrapper, copied from Mundi
  labels.rs             # Translatable names and formatting shared by views
  ui_tests.rs           # Ignored tests that need a display
  choice.rs             # Game logic (no widgets): ChoiceSet, a bitmask of choices <-> letters
  operation.rs          # Game logic: Operation, OperationSet (ChoiceSet of "asmd")
  level.rs              # Game logic: Level 1..5 and the operand ranges
  generator.rs          # Game logic: question generator
  comparison.rs         # Game logic: Decimal, Comparison, ComparisonKind, Part and the
                        # comparison generator
  fraction.rs           # Game logic: Fraction (with an optional whole part)
  fraction_label.rs     # FastmathFractionLabel: a stacked fraction
  round.rs              # Game logic: Mode, Prompt/Answer, round state machine,
                        # GameConfig, RoundResult
  leaderboard.rs        # Game logic: top-10 JSON store
resources/              # GResource: ui/*.ui, style.css, sounds/*.oga
data/                   # Desktop file, metainfo, GSettings schema, icons
po/                     # Translations
build-aux/              # Devel Flatpak manifest (GNOME 51), pre-commit hook
```

## Architecture

- Every widget is a GObject subclass with a private `imp` module,
  `#[derive(CompositeTemplate)]` bound to `resources/ui/*.ui`, and a public
  `glib::wrapper!`. Views talk to the window through signals
  (`start`, `finished`, `abandoned`, `retry`, `back`).
- The window keeps the start page at the bottom of its `AdwNavigationView`
  and uses `replace()` to show a game or the results.
- `Round` has no clock. `GameView` passes the time elapsed since the round
  started to `Round::submit`, and calls `finish()` when time runs out. The
  game clock starts when the page is shown, so the page transition does not
  cost time, and stops while the abandon dialog is open.
- The game logic (`choice.rs`, `operation.rs`, `level.rs`, `generator.rs`,
  `comparison.rs`, `fraction.rs`, `round.rs` and `leaderboard.rs`) does not
  use GTK. It uses GLib in `leaderboard.rs` for the data directory and
  logging, and in `round.rs` and `fraction.rs`, where `GameConfig` and
  `Fraction` are boxed types so widgets can take them as construct
  properties. Keep the question generation and scoring there and unit
  tested.
- Questions: addition and subtraction operands are 1..=max, factors and
  divisors are 2..=max. Division picks the divisor and the quotient and
  multiplies them, so it is always exact. The same question never comes twice
  in a row.
- Comparisons: `Round` holds a `Prompt` (an arithmetic `Question` or a
  `Comparison`) and takes an `Answer` (a number or an `Ordering`). The
  generator picks a selected `ComparisonKind` (whole numbers, decimals,
  fractions, calculations) and then the answer, so each answer comes up a third of the
  time. The level sets the difficulty of each kind (see the table in
  `comparison.rs` and the README); `labels::comparison_kind_description`
  shows it as the subtitle of each switch row. `Decimal` stores thousandths
  plus the places shown, so 8.3 and 8.30 are equal but written differently.
  Sides are compared exactly as fractions (cross-multiplying), so 1/3 and
  0.33 differ. `Prompt::parts()` returns text and `Fraction` parts;
  `GameView` turns them into labels and `FastmathFractionLabel` widgets in
  `question_box`. The decimal separator is a
  translatable string (context "decimal separator").
- Leaderboards are JSON files in `$XDG_DATA_HOME/fastmath/`, one per
  operations/level/duration (`asmd-2-120.json`, or `c-wdfc-2-120.json` for
  comparisons), ranked by correct answers and then by a lower average time
  per answer.
- GSettings: `mode` (`arithmetic` or `comparison`), `operations` (letters
  `a`, `s`, `m`, `d`), `comparisons` (letters `w`, `d`, `f`, `c`), `level`,
  `duration-secs`, `sound-effects`, `player-name`, and the
  `.state.window` child for the window size.

## Non-Obvious Patterns

- **Dual build systems**: `build.rs` fills `src/config.rs.in` from environment
  variables that Meson sets. Plain Cargo builds use defaults.
- **Meson and the target directory**: the Meson cargo target copies the binary
  from `./target`, so in an environment with `CARGO_TARGET_DIR` set, link
  `./target` to it.
- **Sounds** are GResources played with `gtk::MediaFile`. The GNOME runtime
  provides the GStreamer backend, and Flatpak needs `--socket=pulseaudio`.
- **Toolkit versions**: GTK 4.20 and libadwaita 1.8 (for
  `AdwShortcutsDialog`). On older distributions such as Ubuntu 24.04, build
  and run inside the GNOME Flatpak SDK.
- **Display tests** run as one `#[test]` because the widgets start clocks on
  the default main context, which only one thread can own. A button only
  finds its action (`game.compare`) once it is inside a window, so tests
  that click buttons put the view in a window that is never shown.

## Tooling & Config

- **CI** (`.github/workflows/ci.yml`): on `ubuntu-26.04`, `cargo fmt --check`,
  `meson format --check-diff` (fails if the Meson files are not formatted),
  `cargo clippy --all-targets -D warnings`, `cargo build`, `cargo test`, then
  Meson setup, compile and test (`desktop-file-validate`, `appstreamcli
  validate`).
- **Pre-commit hook**: `ln -s ../../build-aux/pre-commit .git/hooks/pre-commit`
  runs `cargo fmt --check` and formats the code if needed.

## Custom Instructions

### Development Workflow
- **ALWAYS run `cargo fmt` before committing**
- Run `cargo clippy --all-targets -- -D warnings`
- Development: `glib-compile-schemas data/ && GSETTINGS_SCHEMA_DIR=data cargo run`
- Production: `meson setup builddir && meson compile -C builddir && meson test -C builddir`
- Format the Meson files with `meson format -i -c meson.format meson.build po/meson.build data/meson.build data/icons/meson.build`
  (2 spaces, one argument per line)
- Tests that need a display, from a desktop session (they do not show a
  window): compile the schema into a directory, then
  `GSETTINGS_BACKEND=memory GSETTINGS_SCHEMA_DIR=<dir> cargo test -- --ignored --test-threads=1`
- Translations: `meson compile -C builddir fastmath-pot`, then update `po/*.po`

### Release Process
1. Update version in `Cargo.toml` and `meson.build`
2. Add release entry in `data/io.github.nacho.fastmath.metainfo.xml` with:
   - New version number
   - Release date (YYYY-MM-DD format, use current date)
   - List of changes since last release
   - Keep `translate="no"` on the release `<description>`, the release notes are not translated
3. Generate changelog: `git log vPREVIOUS..HEAD --oneline --no-merges`
4. Organize changes into categories: **Added**, **Improved**, **Fixed**, **Updated**
5. Run `cargo fmt` and `cargo update -p fastmath`
6. Commit as "Release X.Y.Z"
7. Tag `vX.Y.Z`
8. Push changes and tags: `git push && git push --tags`

### Code Conventions
- All user-visible strings must be translatable via gettext
- Log with `glib::debug!` and `glib::warn!` (domain `fastmath`, import
  `crate::G_LOG_DOMAIN`), not `println!`; use them as statements ending in `;`
- Separate UI templates (XML) from logic (Rust)
- No Cairo; use GTK for any drawing
- Application icon MUST follow the GNOME HIG palette
- Keep dependencies minimal and well-justified
